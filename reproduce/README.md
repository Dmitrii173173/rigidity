# Пересчёт таблиц

Стенды печатают по одной сцене за прогон; таблицы статьи сводят восемь.
Свёртки здесь не было, и таблицы нельзя было пересчитать, хотя §IV-C
обещает обратное. Это оно.

```sh
cargo build --release -p rigidity-cli --example real_data \
            -p rigidity-graph --example basin --example global --example eth_survey
./reproduce/run_all.sh          # 80 прогонов, около 40 минут на M5
python3 reproduce/collect.py results
python3 reproduce/table3.py    results
```

Датасеты нужны все восемь: `datasets/fetch.sh`, а для крупных
последовательностей `datasets/fetch_chunked.sh` — сервер ETH рвёт длинные
соединения, и `curl -C -` при обрыве откатывается в начало.

Файл поз стенды ищут рядом со сканами: если `pose_scanner_leica.csv` лежит
только в `csv_global`, скопируйте его в `csv_local`.

## Что чем воспроизводится

| Таблица | Стенд | Условия | Свёртка |
|---|---|---|---|
| V-B | `real_data` | 360°, 30 пар | `collect.py` |
| III | `eth_survey` | 30 станций, пять полей зрения | `table3.py` |
| IV | `basin` | 30 станций, 360°/±90°/±40° | `collect.py` |
| V | `global` | все станции, 360° | `collect.py` |

Table II сводить нечего — `bias.rs` печатает свою строку целиком:

```sh
RIGIDITY_INIT_SIGMA=0.10 cargo run --release -p rigidity-graph --example bias -- <каталог> 12
```

## Оговорка про Table III

`table3.py` считает победой улучшение худшей станции более чем на заданный
запас. Запас — решение автора, и он должен стоять в подписи к таблице: сам
стенд объявляет вариант лучшим при любом улучшении, а при нулевом поле
взвешивание есть сама JᵀWJ, и она объявляется лучшей. Это численный шум,
и по такому правилу «побед» набирается втрое больше настоящих.
